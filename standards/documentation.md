# Documentation standard

A maintainable project should document:

- purpose, scope, setup, scripts, and deployment;
- architecture and module ownership;
- environment variables and external service requirements;
- public component contracts: props, events, slots, defaults, examples, and caveats;
- testing strategy and CI quality gates;
- security assumptions, data persistence, and recovery;
- release and rollback procedures.

Keep docs aligned with actual source code. Do not invent component APIs from naming or intended design.
